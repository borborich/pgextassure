## Conservative grouping result

One SQL-heavy upgrade history accounted for nearly all duplicated locations.
Its 765 findings became 190 root causes:

- 387 `sql.security-definer-public-execute` locations became 95 routine-scoped
  root causes;
- 376 `sql.security-definer-search-path` locations became 93 routine-scoped
  root causes;
- two other findings remained two separate root causes.

The complete grouped report retained all 765 source locations while shrinking
from 644,567 bytes to 295,418 bytes, a 54.2% reduction relative to the regular
JSON report for the same scan.

The strategy does not merge rules based only on similar snippets or filenames.
It requires an explicit parsed routine identity and matching extension artifact
scope. Every source location remains attached to its group, and all
non-supported rule families remain one root cause per finding.

The absence of compression in the other seven completed repositories is an
expected safety property, not a failed optimization: the current strategy found
no repeated semantic routine identity it was authorized to merge. Project-level
security interpretation remains behind the review and disclosure gate in the
pilot methodology.
